## Input

**Бизнес-потребность:** тренировка таблицы умножения с разбивкой по фиксированному первому
множителю, чтобы отрабатывать по одному «столбику» таблицы за сессию. Формат тот же, что у
остальных тренажёров в приложении.

**Предложенное решение (вход, не мандат):** 4-й столбец на главном экране из 9 кнопок
«Умножение 1» … «Умножение 9»; каждая открывает экран, где N умножается на числа 2..9.

**Известные ограничения:**
- Один файл `Math.py`, tkinter, без новых зависимостей.
- Строго по аналогии с существующими 9 экранами (визуал, тайминги, механика).

**Предполагаемый контекст:** пользователь знает своё приложение; формулы неправильных вариантов
он задал сам, но в списке есть внутренние противоречия (см. Open Gaps).

### Расхождение с паттерном, требующее фиксации в спеке

Пользователь явно потребовал кнопку сброса («есть кнопка очистить»), но ни у одного из трёх
экранов нового паттерна её нет. **Требование пользователя выигрывает**: кнопка включается, а
оформление берётся у старых экранов — `text="Сбросить"`, Arial 16, `pack(pady=5)`,
`command=self.reset_stats`; `reset_stats` обнуляет оба счётчика и вызывает `update_stats()`
(`Math.py:179-180, 205-208`). Расхождение в названии: пользователь сказал «очистить», в коде
везде «Сбросить» — берём «Сбросить» ради согласованности, отметить в Decisions Made.

### Побочная находка: существующий баг в NoBorrowSubtractionScreen (вне scope)

`Math.py:1359-1373` — операнды перепутаны. Экран называется «Минус: 1-значное из 2-значного»,
но `self.correct_answer = num1 - num2`, где `num1` однозначное, а `num2` двузначное: вопрос
выходит «3 - 47 = ?» с ответом -44 вместо «47 - 3 = ?». Условие `units2 >= num1` с комментарием
«no borrow» написано для порядка `num2 - num1`, то есть замысел подтверждает перестановку.
**Прямое следствие для этой спеки:** `NoBorrowSubtractionScreen` — главный образец для нового
экрана, и слепое копирование его `generate_question` перенесло бы дефект. Сам баг в scope этой
спеки не входит, вынести в `## Out of Scope` отдельной строкой.

## Open Gaps (вход в фазу 2)

1. **Пятое или шестое правило неправильного варианта.** Пользователь перечислил 6 пунктов, но
   `(3*7+1)` и `3*7+1` — одно и то же выражение. Различных формул пять:
   `(a-1)*b, (a+1)*b, a*(b-1), a*b-1, a*b+1` — ровно под 5 неправильных слотов из 6 кнопок.
   Опечатка или имелось в виду `a*(b+1)` шестым (тогда нужно правило отбрасывания одного)?
2. **Выбор второго множителя.** «1/8» указывает на равномерное случайное `b ∈ {2..9}`;
   «умножается со всеми числами от 2 до 9» допускает перемешанный цикл с гарантированным
   покрытием всех 8. Читается по-разному, различие наблюдаемо.
3. ~~**Коллизии значений вариантов.**~~ ЗАКРЫТ в раунде 1: добор из резервного списка.
   Точная механика коллизий — перебраны все 15 пар формул, сталкиваются **четыре**, каждая в 8
   вопросах из 72: `(a-1)*b == a*(b-1) ⇔ a == b`; `(a+1)*b == a*(b+1) ⇔ a == b`;
   `a*(b-1) == a*b-1 ⇔ a == 1`; `a*(b+1) == a*b+1 ⇔ a == 1`. Остальные 11 пар не сталкиваются
   ни при каких `a ∈ 1..9`, `b ∈ 2..9`. Четвёртую пару нашёл `spec-author`, подтверждено
   перебором — первая версия этого списка была неполной.
4. **Чем продолжается резервный список за пределами шести формул.** Нужен ещё минимум один
   источник значения для 16 вопросов с нехваткой. Кандидаты: `a*b-2` / `a*b+2`,
   `(a+1)*b+1`, `a*(b+2)`, либо «отбросить не случайную, а ту, что коллидирует» (тогда
   отбрасывания не происходит и шесть формул дают 5 различных... проверить: на квадратах даёт
   ровно 4, значит не спасает).
5. **Допустим ли 0 как неправильный вариант** на экране «Умножение 1» (`(a-1)*b = 0`). История
   коммитов говорит, что на других экранах ноль убирали намеренно.

### Итоговый алгоритм генерации вариантов (проверен исчерпывающим прогоном)

1. `correct = a * b`, где `a` фиксировано экраном (1..9), `b` случайно из 2..9 и `b != previous_b`.
2. Шесть формул дистракторов: `(a-1)*b, (a+1)*b, a*(b-1), a*(b+1), a*b-1, a*b+1`.
   **Одна отбрасывается случайно** на каждом вопросе — остаётся пять.
3. Значения пяти оставшихся фильтруются по порядку: отбрасывается равное `correct`, равное `0`
   и уже попавшее в набор.
4. Пока набрано меньше пяти — добор из резерва `correct+2, correct-2, correct+3, correct-3, …`,
   с теми же фильтрами (не `correct`, строго > 0, не дубликат).
5. Правильный ответ добавляется шестым, все шесть перемешиваются по кнопкам.

**Проверено запуском** по всем 432 комбинациям (9 значений `a` × 8 значений `b` × 6 вариантов
отброшенной формулы): всегда ровно 6 различных строго положительных значений, правильный ответ
всегда среди них. Резерв срабатывает в 96 комбинациях из 432: один добор в 32, два в 56, три в 8
(худший случай — экран «Умножение 1», где запрет нуля и две пары коллизий действуют вместе).
Распределение перепроверено после правки `spec-author`: первая версия (32/58/6) занижала глубину,
потому что считала доборы по принадлежности значения набору формул, а добор может совпасть со
значением отброшенной или запрещённой формулы.
Примеры: `a=1,b=2 → [1,2,3,4,5,6]`; `a=3,b=3 → [6,8,9,10,11,12]`; `a=9,b=9 → [72,80,81,82,83,90]`.

### Находка, вскрытая ответом на Gap 1 (проверено запуском, не рассуждением)

Шести формул **не хватает** на пять различных дистракторов в 16 из 72 вопросов: максимум различных
значений падает до **4** на квадратах (`b = a`, по одному вопросу на каждом экране `a=2..9`) и на
**всех 8 вопросах** экрана «Умножение 1» (там `a*(b-1) == a*b-1` и `a*(b+1) == a*b+1`
одновременно). То есть резерв из Gap 3 обязан выходить **за пределы шести формул**, иначе шестая
кнопка остаётся пустой либо дублирует. → новый Gap 4.

Попутно: при `a=1` формула `(a-1)*b` даёт **0**. Последний коммит в истории — `make 0 impossible
with minus + plus`, то есть ноль как вариант пользователь целенаправленно убирал на других
экранах. → новый Gap 5.
